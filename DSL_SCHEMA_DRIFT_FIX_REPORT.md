# DSL Schema Drift Fix Report

## Root Cause

The **schema drift** between the playwright-agent and playwright-runner-job caused the runner to reject valid DSL generated by the LLM. The agent's schema marked `preconditions`, `required_inputs`, and `diagnostics` as **optional** in `ExecutionProfileDsl`, but the runner's validation logic treated these fields as **required**, incorrectly rejecting DSL that omitted them. Additionally, the runner did not properly handle explicit `null` values for optional nested objects like `generated_plan` and `execution_profile`, which the LLM generated as `null` instead of omitting entirely.

## Impact

- **Previous behavior**: DSL generated by LLM (validated ✓ by agent) was rejected as `invalid_spec` by runner ✗
- **New behavior**: DSL passes validation in both agent and runner, eliminating the `invalid_spec` error
- **No regression**: Phase 0 lock to OpenAI codex.sale/gpt-5.4 remains intact; `fallback_used: false` is preserved

## Files Modified

1. **playwright-runner-job/src/engine/dsl.ts**
   - Updated TypeScript interfaces to mark optional fields as nullable
   - Fixed validation functions to accept optional/null values correctly

### Validation Logic Changes

**validateExecutionProfile()** and **validateGeneratedPlan()** now:
- Accept `undefined` values for optional array fields (`preconditions`, `required_inputs`, `diagnostics`, `preflight_checks`)
- Only validate array contents if the field is provided and not `null`
- Check `input.field !== undefined && input.field !== null` before processing

**Case-level validation** now:
- Treats `null` as "not provided" for `execution_profile` and `generated_plan`
- Skips validation if either field is `null` or `undefined`
